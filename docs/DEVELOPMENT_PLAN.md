## 1 技术基线（冻结，不再讨论）

| 层 | 选型 | 说明 |
|---|---|---|
| 数据库 | PostgreSQL 17（Postgres.app） | 课程最终平台；本地单实例，不做分布式 |
| 驱动 | Python 3.11 + `psycopg[binary]` 3.x | 不用 ORM；SQL 全部写在 `.sql` 文件 |
| 应用 | FastAPI + Jinja2 + HTMX + 少量 CSS | 5 个页面，服务端渲染，不引入前端构建链 |
| 客户端 | DataGrip（学生授权）或 DBeaver CE | 同时连接 SQLite 快照与 PG |
| 图 | draw.io | 沿用现有 ER/EER 源文件 |
| 版本 | Git + GitHub（现有仓库） | `main` 受保护，全部走 PR |
| 环境 | macOS + `DATABASE_URL` | 凭据只放 `.env`，禁止入库 |

**明确不做**：ORM（SQLAlchemy/Django/Prisma）、前端框架、Docker 编排、云数据库、ML 模型。理由见 `DBMS_CLASSIFICATION.md`：评分看的是数据库设计与 SQL，不是应用工程。

**命名规则**

- SQL 文件：`NN_主题.sql`，两位序号，同目录内按序号执行。
- 查询文件：`q01_资产追溯.sql` … `q08_数据质量告警.sql`。
- 截图：`YYYY-MM-DD_主题_角色代号.png`，存 `output/`（不入库）。
- 文档：`YYYY-MM-DD_主题.md`，中文标题不翻译。
- 分支：`feat/pg-schema`、`data/pg-import`、`app/crud-pages`、`docs/report`。

**数据文件规则**

- 超过 20 MB 的单个文件改用 Git LFS；当前最大值 7.4 MB，暂不需要。
- `data/raw/`、`data/part3_handover/`、`*.zip` 永不入库。
- 生成物必须能用 `scripts/` 重建；不能重建的才入库。
- 数据库运行产生的 `-wal` / `-shm` / `-journal` 不入库。

## 3 开发流程（每个任务的六步）

```
认领 Issue → 建分支 → 本地实现并自测 → 提 PR → 24h 内评审 → squash 合并 + 关 Issue
```

1. **认领**：在 Issue 下评论 `take`，给自己加 `doing` 标签。一人同时只做一件事（WIP=1）。
2. **分支**：从最新 `main` 切出，生命周期 ≤ 2 天；超过 2 天说明任务没拆细。
3. **自测**：DB 类任务必须在空库上从 `00_schema.sql` 重跑一遍；数据类任务贴行数对比；应用类任务附截图。
4. **PR**：标题 `[任务ID] 摘要`，正文用模板（见 §9），关联 Issue。单个 PR 控制在 400 行以内；纯 SQL 生成文件除外。
5. **评审**：固定结对，24 小时内给结论。评审只看三件事：能否从空库复现、是否破坏已冻结接口、是否留下证据（截图/EXPLAIN）。
6. **合并**：squash merge，删除分支，关闭 Issue。`main` 必须随时可重建。

### 3.1 提交信息

```
<type>(<scope>): <一句话>

type: feat | fix | docs | data | chore | test
scope: db | app | report | data | ops
例：feat(db): port module-4 seven tables to PostgreSQL
    fix(db): replace overlap triggers with EXCLUDE constraint
```

## 6 五人分工

### 6.1 分线原则

1. **按交付物分线，不按业务板块分线。** 五个板块的概念设计已经完成；继续按板块会形成五条互不依赖的线，最后没人做集成。
2. **先集中，后散开。** 11/27–12/02 至少 3 人压在 PG 关键路径上；12/03 之后再分给应用与报告。关键路径不结束，应用和报告都是空转。
3. **一人一任务（WIP=1）**，任务粒度 ≤ 1.5 天，超过就拆。
4. **接口先冻结**，应用层按冻结后的模式写，避免返工。
5. **报告素材边做边截**，不搞最后两天补报告。
6. **异步为主**，只有两次同步会；其余用 Issue 和群聊。

## 8 质量与验收

### 8.1 Definition of Done

| 类型 | 完成标准 |
|---|---|
| DDL | 空库执行 `00→07` 全部成功；`\dt` 27 表；`\dv` 14 视图；重复执行幂等 |

## 附录 A SQLite → PostgreSQL 转换决策

| SQLite 写法 | PostgreSQL | 决策 |
|---|---|---|
| `TEXT` 存 ISO8601（`+08:00`） | `timestamptz` | 导入 `::timestamptz`；应用层 UTC 存储、+08 展示 |
| `TEXT` 业务主键（`BATT_001`、`SIM-PACK-0001`） | `text` | **不改 uuid 类型**，避免 27 表外键连锁改动 |
| `GLOB 'SIM-PACK-[0-9][0-9][0-9][0-9]'` | `~ '^SIM-PACK-[0-9]{4}$'` | 正则 |
| `julianday(x) IS NOT NULL` | 删除 | `timestamptz` 已保证 |
| `length(trim(x)) > 0` | `btrim(x) <> ''` | 或 `x ~ '\S'` |
| `RAISE(ABORT, ...)` 触发器 | `CHECK` / `EXCLUDE` / `PL/pgSQL` | 先声明式，后过程式 |
| `REAL` 电压/容量 | `numeric(10,4)` | 测量点用 `double precision` |
| `INTEGER` 0/1 | `boolean` | 语义化 |
| `PRAGMA foreign_keys = ON` | 删除 | PG 始终开启 |
| `AUTOINCREMENT` | `GENERATED ... AS IDENTITY` | 仅自增表；现有多为业务码 |
| `datetime('now')` | `now()` | 统一时区 |

**触发器分诊纪律**：每条触发器先回答“能不能用约束表达”。能，就改约束并写反例测试；不能，才写 `PL/pgSQL`，并在 `04_triggers.sql` 顶部注明理由。
